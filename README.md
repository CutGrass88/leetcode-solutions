## Repository Structure

Each solution has one home based on its main data structure or topic. The index below records other techniques used in the solution, since a problem can fit more than one category.

```text
arrays/            Array problems
bit_manipulation/  Binary digits, bitwise operations, and bit masks
linked_lists/      Linked-list problems
math/              Number and arithmetic problems
sorting/           Sorting algorithm practice
stacks/            Stack problems
strings/           Text and character problems
trees/             Tree problems
ADS/               Numbered practice sets, kept in their original groups
```

### Choosing a Folder

- Start with the main subject of the problem: arrays, strings, linked lists, trees, numbers, or bits.
- Use a specialised topic when it is central to the exercise. For example, Valid Parentheses belongs in `stacks/`, and sorting implementations belong in `sorting/`.
- Keep secondary techniques in the index instead of making duplicate copies. Two Sum stays in `arrays/` and uses a hash map; Reverse Vowels stays in `strings/` and uses two pointers.
- Increasing Triplet Subsequence belongs in `arrays/`: it scans an array using a greedy approach and does not use a tree.
- Reverse Bits belongs in `bit_manipulation/`, regardless of its difficulty. Its file is a starting point for the next solution.
- Add new topic folders when needed, such as `graphs/` or `dynamic_programming/`.
